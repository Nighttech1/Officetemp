### [C-83] Пакет ИУЛ: то же окно мастера + вертикальные вкладки ИУЛ + «Сформировать ИУЛы»
- **Зона:** Мастер ИУЛ / пакетная загрузка PDF
- **Факт:** Пакет уже создаёт несколько ИУЛ, но UX отличается; кнопка «Скачать ИУЛы».
- **Ожидание:** Как при одном PDF: те же шаги. Слева вертикальный список ИУЛ (как список подписантов). Справа кнопка «Сформировать ИУЛы». Каждый ИУЛ — отдельная вкладка с полным мастером.
- **Приоритет:** P0
- **Зона:** Frontend

### [C-84] Хэш файла при пакетной загрузке не должен быть «в 2 раза длиннее»
- **Зона:** Шаг 1 / seedIulFromPdf
- **Факт:** При пакетной загрузке хэш визуально/по длине больше, чем при одиночной.
- **Ожидание:** Тот же алгоритм (по умолчанию SHA-256 → 64 hex), одна длина, один проход hashFile по копии байтов файла.
- **Приоритет:** P0
- **Зона:** Frontend

### [C-85] Шаг «Подписи»: характер работы слева, автокартинка + загрузка, настройки ролей проекта
- **Зона:** Шаг 3 мастера ИУЛ
- **Ожидание:**
  1. Слева вкладки по **характеру работы** (role), не по фамилии.
  2. Картинка подписи авто из библиотеки по фамилии; если нет — кнопка «Загрузить подпись PNG/JPEG» → сразу в поле и в библиотеку проекта.
  3. Кнопка настроек проекта: фиксированный набор характеров работы + куда писать «остальные» найденные в PDF; действует на все ИУЛ проекта.
- **Приоритет:** P0
- **Зона:** Frontend
