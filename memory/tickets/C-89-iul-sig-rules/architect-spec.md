# Architect spec — W-38 (C-89 / C-90)

## Правила заказчика

1.1 Пара (характер работы, фамилия) — уникальна, без дублей строк.  
1.2 Порядок характеров = порядок `fixedRoles` в настройках проекта.  
1.3 Версия пустая или литерал `0` → в бланке `-`.  
1.4 Фамилия в роли ГИП не может встречаться в других ролях (оставляем только строку ГИП).  
1.5 Обозначение = полный шифр + приписки (Изм. N); Наименование документа = текстовое название раздела; подписи колонок уточнить.

## Реализация

### Frontend `docs-store.ts`
Переписать `applyProjectRoleSettings` → нормализация:
1. канонизация ролей / overflow;
2. фильтр ГИП-эксклюзив;
3. дедуп по `(norm(role), norm(surname))`;
4. сборка в порядке `fixedRoles`, затем overflow; пустые слоты для отсутствующих fixedRoles — по одной пустой строке на роль.

Вызывать из `iul-seed` и `InfoSheetWizard.buildSigsFromStamp`.

### Frontend `iul-hash.ts`
`iulVersionCell`: пусто / `0` → `-`.

### Frontend labels
Превью + PDF: «Обозначение документа», «Наименование документа».  
Wizard: placeholder версии без «0».

### Backend `iul_stamp._filename_hints`
- Изм.N вклеивать в `doc_designation` (не в `doc_version`).
- `doc_version` из Изм не заполнять.
- `doc_name` = текстовый хвост без шифра.
- При merge штампа: если в имени файла был Изм, а designation со штампа без него — дописать суффикс.

## Acceptance
Пакет/одиночный PDF: нет дублей роль+фамилия; порядок как в настройках; ГИП уникален по фамилии; обозначение с Изм; наименование — слова; версия `-` если нет числа изменения.
