# Системная архитектура: SaaS-платформа автоматизации документооборота

## 1. Общая концепция и позиционирование
Платформа представляет собой высоконагруженный B2B SaaS-сервис (с возможностью On-Premise развертывания). Основная задача — потоковая генерация документов форматов `.docx` и `.pdf` на основе пользовательских шаблонов и динамических внешних данных с **гарантированным сохранением сложной верстки** и строгим соблюдением **152-ФЗ**.

## 2. Архитектурный стек

### 2.1. Инфраструктура и Безопасность (Контур 152-ФЗ)
- **Хостинг:** Только облачные провайдеры на территории РФ (Yandex Cloud, VK Cloud, Selectel) для соответствия 152-ФЗ (хранение ПДн граждан РФ).
- **Изоляция данных (Multi-tenancy):** Логическая изоляция на уровне базы данных (Row-Level Security) или физическая изоляция схем (PostgreSQL Schemas) для каждого клиента.
- **Шифрование:** TLS 1.3 для передачи данных, AES-256 для хранения чувствительных ключей доступа (к API внешних таблиц).

### 2.2. Backend (Ядро генерации и API)
- **Фреймворк:** Python + FastAPI (асинхронный, быстрый, идеально подходит для работы с I/O задачами и документами).
- **База данных:** PostgreSQL (надежное хранение пользователей, реестров шаблонов и логов генерации).
- **Система очередей (High-load):** Celery + Redis / RabbitMQ. *Критично для сегмента образовательных учреждений (генерация 1000+ дипломов за раз).*
- **Движок рендеринга документов:**
  - `docxtpl` (на базе `python-docx` + `Jinja2`) — модернизированный под работу с динамическими таблицами (решение проблемы "Formatting Breaks").
  - `libreoffice-headless` (в изолированном Docker-контейнере) — для идеальной конвертации сгенерированных `.docx` в `.pdf` без потерь шрифтов.

### 2.3. Frontend (Клиентская часть)
- **Фреймворк:** React / Next.js или Vue 3 (SPA для обеспечения плавного "бесшовного" пользовательского опыта без перезагрузки страниц).
- **Интерфейс:** No-code конструктор. Drag-and-drop зона для загрузки файлов, визуальный маппинг колонок (Excel/Google/Яндекс) на теги внутри Word-шаблона.

### 2.4. Интеграционный слой (Data Connectors)
- **Модуль парсинга Excel:** `pandas` / `openpyxl` (работа с локально загруженными таблицами реестров).
- **API Коннекторы:** 
  - Google Sheets API (OAuth 2.0 / Service Accounts).
  - Яндекс Таблицы API.

### 2.5. Почта и коммуникации
- **Транзакционные письма:** контактная форма, восстановление пароля (SMTP; токены только в виде hash).
- **Маркетинг (баннеры / предложения):** отдельное согласие `marketing_opt_in` (не смешивать с согласием на обработку ПДн); кампании `email_campaigns` + Celery `send_marketing_campaign`; рассылка только opted-in; в каждом письме ссылка отписки `/unsubscribe`.
- **ПДн:** email получателей только через `PiiService`; в таблицах доставок — `user_id`, без сырого email.

## 3. Решение ключевых "Болей" (Pain Points)

1. **Formatting Breaks (Сломанная верстка юристов):** 
   Вместо классического Mail Merge используется умная подмена XML-тегов через Jinja-синтаксис внутри `docxtpl`. Движок будет модифицирован так, чтобы не трогать стили параграфов (w:pPr) и таблиц (w:tblPr) в архиве DOCX.
2. **Динамические списки (Счета и спецификации B2B Sales):**
   Реализация тегов циклов (`{% tr for item in items %}`). Движок автоматически копирует строку таблицы (XML-узел `w:tr`) нужное количество раз, сохраняя заливку ячеек и объединенные границы.
3. **Производительность (Event-индустрия):**
   При загрузке списка на 1000 строк, FastAPI отдает задачу в Celery. Celery разбивает генерацию на 10 параллельных воркеров. Итог: архив `.zip` с 1000 PDF-сертификатов готов за 2-3 минуты.
