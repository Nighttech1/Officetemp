# ТЗ: обучающая HTML-страница «Стек приложения Doc SaaS»

**Версия:** 1.0  
**Дата:** 2026-09-30  
**Для кого:** начинающий программист, который учится на роль ИИ-фулстек архитектора  
**Цель страницы:** понять «из каких кубиков собрано» наше приложение — без сложных терминов, с интерактивной схемой и короткими уроками

---

## 1. Что это за приложение (одним абзацем)

Это **облачный сервис для бизнеса (SaaS)**, который помогает автоматически делать много документов Word (`.docx`) и PDF.  
Пользователь загружает шаблон (например, накладную или договор), подключает таблицу с данными (Excel / Google / Яндекс), связывает колонки с полями в шаблоне — и получает готовые файлы.  
При этом важно хранить персональные данные по правилам **152-ФЗ** (закон РФ о персональных данных).

**Рабочее имя продукта в репозитории:** Doc SaaS (платформа автоматизации документооборота).

---

## 2. Задача этой страницы (что нужно сделать)

Сделать **одну HTML-страничку** (можно с CSS и небольшим JavaScript), которую можно открыть на обучающем сайте.

На странице должны быть:

1. **Интерактивная схема стека** — блоки, по которым можно кликать.
2. **Обучающие тексты** — при клике на блок справа (или снизу на телефоне) появляется простое объяснение: что это, зачем нужно, аналогия из жизни.
3. **Путь данных «как работает запрос»** — короткая анимация или пошаговая подсветка: от кнопки в браузере до готового файла.
4. **Глоссарий новичка** — мини-словарь терминов внизу страницы.

Страница **не** должна подключаться к реальному API и **не** должна менять продакшен-код. Это только учебный материал.

## 3. Стек приложения «на пальцах» (содержание урока)

Ниже — материал, который **обязан** попасть на страницу (можно перефразировать, смысл сохранить).

### 3.1. Картинка целиком (верхний уровень)

Представь завод:

| Часть завода | В приложении | Простыми словами |
|--------------|--------------|------------------|
| Витрина и пульт управления | **Frontend** (то, что видит человек) | Сайт в браузере: кнопки, формы, кабинет |
| Цех и диспетчер | **Backend / API** | Сервер принимает команды и решает, что делать |
| Склад карточек | **База данных PostgreSQL** | Надёжное хранилище пользователей, проектов, логов |
| Очередь заказов | **Redis + Celery** | Если документов много — задачи встают в очередь и делаются фоном |
| Станок документов | **Doc Engine** | Подставляет данные в Word и делает PDF |
| Склад файлов | **Хранилище файлов** (диск / S3 / MinIO) | Лежат шаблоны Word и готовые архивы |
| Охрана | **Безопасность + 152-ФЗ** | Логин, права доступа, изоляция данных клиентов |

### 3.2. Frontend (лицо приложения)

**Что стоит в проекте сейчас:**

- **React** — библиотека для сборки экранов из «кирпичиков» (компонентов).
- **Next.js 15** — каркас вокруг React: страницы, маршруты, сборка сайта.
- **TypeScript** — JavaScript с проверкой типов (меньше глупых ошибок).
- **Tailwind CSS** — быстрая вёрстка через готовые классы стилей.
- **GSAP / Framer Motion / Motion** — библиотеки анимаций (плавные появления, скролл).
- **Radix UI** — доступные готовые куски интерфейса (вкладки, аккордеон).

**Аналогия:** витрина магазина + касса. Человек нажимает кнопки здесь, а «мозг» и склад — сзади.

**Что умеет кабинет (смысл для схемы):**

- вход / регистрация;
- библиотека шаблонов Word;
- связка колонок таблицы с тегами в шаблоне (маппинг);
- запуск генерации и скачивание результата.

### 3.3. Backend (мозг и API)

**Что стоит в проекте:**

- **Python** — язык серверной части.
- **FastAPI** — фреймворк: быстро принимает HTTP-запросы и отдаёт ответы (часто JSON).
- **JWT** — «пропуск» после логина (токен), чтобы сервер знал, кто ты.
- **Alembic** — миграции: аккуратные изменения структуры базы данных версиями.

**Аналогия:** диспетчерская. Браузер звонит сюда: «сгенерируй документы»; диспетчер проверяет права и отдаёт работу цеху.

**Типичный порт локально:** API на `http://localhost:8000`, фронт на `http://localhost:3000`.

### 3.4. База данных PostgreSQL

**Зачем:** хранить структурированные данные — пользователи, организации (компании-клиенты), шаблоны, задания на генерацию, аудит действий.

**Особенности под 152-ФЗ (объяснить на странице простыми словами):**

- данные разных компаний **изолированы** (чужой клиент не должен видеть чужие документы);
- персональные данные (ПДн) обрабатываются отдельно через сервисы профиля;
- есть согласия, выгрузка и удаление/обезличивание своих ПДн.

**Аналогия:** огромный шкаф с папками; у каждой компании свой ящик, чужой ключ не подходит.

### 3.5. Очереди: Redis + Celery

**Проблема:** сделать 1 документ — быстро. Сделать 1000 дипломов сразу — долго, браузер не должен «виснуть».

**Решение:**

1. API кладёт задачу в **очередь** (через **Redis** — быстрый посредник в памяти).
2. **Celery worker** (фоновый работник) берёт задачу и генерирует файлы.
3. Пользователь видит прогресс и потом скачивает ZIP/PDF.

**Аналогия:** талончик в МФЦ. Ты не стоишь у каждого окошка — берёшь номер, система обрабатывает по очереди.

В Docker-compose есть сервисы: `api`, `worker`, `beat` (расписание), `redis`, `db`.

### 3.6. Doc Engine (генерация документов)

**Цепочка:**

1. Шаблон Word с плейсхолдерами вроде `{{ ClientName }}`.
2. Движок **docxtpl** (python-docx + Jinja2) подставляет данные, стараясь **не ломать вёрстку**.
3. Динамические таблицы через циклы (много строк из реестра).
4. Конвертация в PDF (в проекте — контур **dxpdf**, без обязательного LibreOffice в основном сценарии).
5. При массовой генерации — сборка **ZIP**.

**Аналогия:** печатный станок: форма (шаблон) + краска (данные) = готовые бланки.

### 3.7. Источники данных (коннекторы)

Чтобы заполнить документы, данные берутся из:

- **Excel / CSV** (локальный файл) — через pandas / openpyxl;
- **Google Sheets**;
- **Яндекс Таблицы**.

Все источники приводятся к **одному формату JSON**, чтобы движок всегда получал одинаковую «корзину данных».

**Аналогия:** разные поставщики молока, но на кухне всегда один и тот же рецепт.

### 3.8. Хранилище файлов

- Локально / на VPS: папка на диске (`STORAGE_BACKEND=local`).
- Опционально: **MinIO** / S3-совместимое облако (например, Yandex Object Storage).

В базе обычно лежат **метаданные и ключи путей**, а сами тяжёлые файлы — на диске/в объектном хранилище.

### 3.9. Инфраструктура (как это упаковано)

- **Docker Compose** — «коробка» с несколькими сервисами сразу: база, redis, api, worker…
- Разработка: локальный компьютер (localhost).
- Боевой сервер (VPS) — только после явного согласования; данные нельзя терять при пересоздании контейнеров.

### 3.10. Команда ИИ-агентов (контекст для будущего архитектора)

В этом репозитории разработка идёт **ролями**: Оркестратор → Архитектор → Frontend / Backend / Doc Engine / … → Тестировщик → Фиксер → Деплоер → Клиент (приёмка).

На учебной странице достаточно **короткого блока** «как устроена команда» — без копирования всех правил. Смысл: архитектор сначала проектирует, потом пишут код по цепочке, потом проверяют и принимают.

## 4. Интерактивная схема — требования к UX

### 4.1. Узлы схемы (обязательные кликабельные блоки)

Минимум эти узлы:

1. Пользователь (браузер)
2. Frontend (Next.js + React)
3. Backend API (FastAPI)
4. PostgreSQL
5. Redis + очередь
6. Celery Worker
7. Doc Engine (DOCX → PDF)
8. Хранилище файлов
9. Коннекторы данных (Excel / Google / Яндекс)
10. Контур безопасности / 152-ФЗ

Связи стрелками показывать направление потока данных.

### 4.2. Поведение

- **Клик / тап по узлу** → в панели «Урок» открывается текст этого узла (заголовок, 3–7 предложений, аналогия, «что запомнить»).
- **Кнопка «Проиграть путь документа»** → по очереди подсвечиваются узлы: Frontend → API → (очередь) → Worker → Doc Engine → Хранилище → снова Frontend (скачивание).
- **Кнопка «Сбросить»** → убрать подсветку, вернуть стартовый текст.
- На **мобильном** (≈390px): схема сверху или упрощённый вертикальный список; урок снизу. Без горизонтального скролла страницы.
- На **desktop** (≈1440px): схема слева/по центру, урок справа.

### 4.3. Тексты в панели «Урок»

Для каждого узла структура:

```
Название
Зачем это нужно (1–2 предложения)
Как устроено в нашем проекте (конкретные технологии)
Аналогия из жизни
Что запомнить архитектору (1 буллет)
```

Язык: **простой русский**, без «воды». Термины при первом появлении объяснять в скобках.

## 5. Дополнительные блоки страницы

### 5.1. Шапка

### 5.2. Режим «Путь одной накладной» (сценарий)

Пошаговый текст (можно синхронизировать с анимацией):

1. Пользователь открывает кабинет и загружает шаблон Word.  
2. Загружает Excel с строками заказов.  
3. Связывает колонки с тегами.  
4. Нажимает «Сгенерировать».  
5. Frontend отправляет запрос на FastAPI.  
6. API создаёт задачу и кладёт в очередь (Celery/Redis).  
7. Worker заполняет DOCX и при необходимости делает PDF / ZIP.  
8. Файл кладётся в хранилище.  
9. Пользователь скачивает результат.

### 5.3. Глоссарий (минимум терминов)

Обязательно объяснить: SaaS, API, Frontend, Backend, База данных, JSON, JWT, Очередь задач, Docker, 152-ФЗ, Tenant / организация, Маппинг, Шаблон, Миграция БД.

### 5.4. Чеклист самопроверки ученика

5–7 вопросов с раскрывающимися ответами, например:

- Чем Frontend отличается от Backend?
- Зачем нужна очередь, если можно генерировать сразу в API?
- Где лежат сами файлы Word — в PostgreSQL или в хранилище?
- Что такое маппинг?
- Почему важна изоляция данных между компаниями?

## 6. Технические требования к реализации страницы

| Требование | Деталь |
|------------|--------|
| Формат | Один `index.html` + при необходимости `styles.css` и `app.js` (или всё в одном файле) |
| Зависимости | Без обязательного React/Next для самой учебной страницы — чистый HTML/CSS/JS, чтобы открывалась везде |
| Размещение | Папка `education/` в этом репозитории **или** встраивание в обучающий сайт пользователя (скопировать файлы) |
| Доступность | Клавиатура: фокус на узлах, Enter/Space открывает урок; достаточный контраст текста |
| Офлайн | Страница должна работать без интернета (не тянуть тяжёлые CDN, если можно обойтись) |
| Язык UI | Русский |

**Не делать в рамках этого ТЗ:** подключение к боевому API, авторизацию, генерацию реальных документов, деплой на VPS.

## 9. Эталонная «шпаргалка стека» (кратко для схемы)

```
[Браузер]
    ↓
[Next.js + React + TypeScript + Tailwind]  ← Frontend :3000
    ↓  HTTP / JSON + JWT
[FastAPI / Python]                         ← Backend API :8000
    ├──→ [PostgreSQL]                      ← данные и метаданные
    ├──→ [Redis] → [Celery Worker]         ← фоновые задачи
    │         ↓
    │    [Doc Engine: docxtpl → DOCX/PDF/ZIP]
    ├──→ [Файловое хранилище / MinIO]
    └──→ [Коннекторы: Excel, Google Sheets, Яндекс Таблицы]

Рядом сквозной слой: безопасность, 152-ФЗ, изоляция организаций
Упаковка: Docker Compose (db, redis, api, worker, beat)
```
